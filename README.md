# Mini Git

커밋 메타데이터를 기록하고 브랜치를 관리하는 Python CLI 학습 프로젝트입니다.
DAG 위상 정렬, BFS 최단 경로, DFS 조상 탐색, 역색인 검색, 직접 구현한 병합 정렬을 제공합니다.
실제 파일 내용은 추적하지 않으며, 종료하면 메모리의 기록은 사라집니다.

## 1. 과제 정보

- 분야: AI/SW 기초 / 자료구조와 알고리즘
- 과제: 파일이 언제 어떻게 바뀌었는지 기록하는 작은 프로그램 만들기
- 필수 과제 / 교육과정 기준 학습시간: 80시간 (실제 수행시간 증명 아님)
- Python 3.10 이상, 외부 패키지 설치 불필요
- 필수 기능 전체 및 선택 기능 MERGE 구현

## 2. 파일 구성과 실행

| 파일 | 역할 |
|---|---|
| main.py | 실행 진입점, 자료구조, 알고리즘 및 REPL |
| README.md | 사용법, 설계, 복잡도 및 검증 설명 |
| test_main.py | 표준 unittest 기반 자동 테스트 12개 |
| .gitignore | Python 캐시 등 제외 |
| START_HERE.txt | VS Code에서 열고 GitHub에 올리는 절차 |

```bash
python main.py
```

Windows에서 python 명령 대신 `py main.py`도 사용할 수 있습니다.
`mini-git>`이 나타나면 아래 명령을 입력합니다. 종료는 `exit` 또는 `quit`입니다.

## 3. 명령 문법

| 명령 | 기능 |
|---|---|
| INIT "Alice Kim" | main 브랜치 생성, HEAD 및 작성자 설정 |
| BRANCH feature | 현재 HEAD를 가리키는 새 브랜치 생성 |
| SWITCH feature | 현재 브랜치 변경 |
| COMMIT "Add login feature" | 현재 HEAD를 부모로 커밋 생성 |
| LOG | 저장소 전체의 부모 우선 로그 |
| LOG --sort-by=date | UTC 생성 시간 오름차순 |
| LOG --sort-by=author | 작성자명 오름차순 |
| PATH <hash1> <hash2> | 무방향 부모 연결의 최단 경로 |
| ANCESTORS <hash> | 자신을 제외한 모든 조상 |
| SEARCH "login" | 소문자로 정규화한 토큰 검색 |
| SEARCH --author="Alice Kim" | 작성자 정확 일치 검색 |
| MERGE feature | 두 HEAD를 부모로 하는 병합 커밋 생성 |
| HELP | 도움말 |
| EXIT / QUIT | 종료 |

명령어 이름은 대소문자를 구분하지 않습니다. 옵션 이름과 값은 표의 소문자를 사용합니다.
공백이 있는 문자열은 따옴표로 감쌉니다. 브랜치명과 작성자명은 대소문자를 구분합니다.
커밋 ID는 출력된 16자리 전체를 입력합니다.

검색은 부분 문자열이 아닌 공백 기준 토큰 검색입니다. `login`과 `login,`는 다른 토큰입니다.
`SEARCH "login feature"`는 두 토큰을 모두 포함하는 AND 검색이며 연속 구문 검색은 아닙니다.
기본 LOG는 현재 브랜치에 국한되지 않고 모든 커밋을 출력합니다.
브랜치 표시는 해당 커밋을 현재 가리키는 브랜치이며 생성 당시 브랜치를 뜻하지 않습니다.

## 4. 실행 예시

새 세션에서 아래를 순서대로 입력합니다.

```text
init "이송하"
commit "Initial commit"
branch feature
switch feature
commit "Add login feature"
switch main
commit "Add payment feature"
log
search "LOGIN"
search "login feature"
search --author="이송하"
log --sort-by=date
log --sort-by=author
path 0000000000000002 0000000000000003
ancestors 0000000000000003
merge feature
path 0000000000000001 0000000000000004
ancestors 0000000000000004
log
exit
```

확인할 결과:

- 기본 로그: 1번 커밋이 2번과 3번보다 먼저 출력됩니다.
- LOGIN 검색: 2번 커밋 1개가 나옵니다.
- 첫 PATH: 2 → 1 → 3입니다.
- 3번의 조상: 1번입니다.
- MERGE: 4번 커밋이 생성되며 부모는 3번과 2번입니다.
- 두 번째 PATH: 동률 경로 중 사전순 최소인 1 → 2 → 4가 나옵니다.
- 4번의 조상: 1, 2, 3번이 중복 없이 나옵니다. 조상의 출력 순서는 DFS 순서입니다.

연결되지 않은 그래프는 프로그램을 다시 실행하고 확인합니다.

```text
init Alice
branch orphan
commit "Root A"
switch orphan
commit "Root B"
path 0000000000000001 0000000000000002
```

첫 커밋 전에 만든 orphan 브랜치는 빈 HEAD를 유지합니다. 따라서 두 개의 독립적인 루트가 생성되고 `No path`가 출력됩니다.

## 5. 핵심 자료구조와 코드 설명

### Commit

불변 dataclass로 `hash`, `message`, `author`, `timestamp`, `parents`를 보관합니다.
`parents`는 튜플입니다. 일반 커밋은 부모 0~1개, 병합 커밋은 서로 다른 부모 2개를 가집니다.

### MiniGit

- `commits`: ID → Commit 객체. 딕셔너리 평균 O(1) 조회입니다.
- `branches`: 브랜치명 → 커밋 ID 또는 None.
- `current_branch` 및 `head`: 현재 브랜치와 해당 브랜치의 커밋 포인터입니다.
- `children`: 부모 → 자식 보조 인접 목록입니다.
- `neighbors`: 부모 연결을 무방향으로 해석한 인접 목록입니다.
- `index`: 키워드와 작성자 역색인입니다.
- `create_commit`: 기존 부모 확인, 유일한 ID 생성, 그래프/역색인 갱신, HEAD 이동을 수행합니다.

ID는 증가 카운터를 16자리 16진수로 표현합니다. 실제 Git의 콘텐츠 해시와는 다릅니다.
최대 ID 이후에는 오류를 발생시켜 ID 재사용을 막습니다. 과제에서 허용하는 카운터 방식을 사용합니다.

### 왜 DAG인가?

커밋의 방향은 자식 → 부모입니다. 새 커밋은 이미 존재하는 커밋만 부모로 지정할 수 있고,
생성된 커밋의 부모는 변경하지 않습니다. 부모를 따라가면 항상 먼저 생성된 커밋으로 이동하므로
자기 자신으로 돌아오는 순환이 생기지 않습니다. 분기와 병합은 가능하지만 사이클은 없는 DAG입니다.

### topological_order: 부모 우선 로그

Kahn 알고리즘을 사용합니다. 출력되지 않은 부모 수를 세고, 부모 수가 0인 커밋부터 큐로 처리합니다.
부모를 출력할 때 자식의 남은 부모 수를 줄입니다. 모든 부모가 처리된 자식만 큐에 넣습니다.
부모 → 자식 보조 그래프를 사용해 부모가 항상 먼저 나오도록 합니다.
전체 정점 수만큼 처리되지 않으면 순환 오류를 발생시킵니다. 시간 O(V + E), 보조 공간 O(V)입니다.

### shortest_path: BFS 최단 경로

목표 노드에서 BFS를 실행하여 각 노드에서 목표까지의 최단 거리를 계산합니다.
시작 노드부터 거리가 정확히 1 감소하는 이웃만 선택하되, 여러 후보 중 ID가 가장 작은 것을 선택합니다.
고정 길이 ID이므로 이 탐욕적인 선택은 `hash1->hash2->...` 문자열의 사전순 최소 최단 경로를 보장합니다.
도달 불가능하면 No path이며, 출발점과 도착점이 같으면 그 커밋 하나만 반환합니다.
시간 O(V + E), 보조 공간 O(V)입니다.

### find_ancestors: 반복형 DFS

스택과 방문 집합을 사용해 부모 방향으로 탐색합니다. 자신은 제외하고 조상 중복을 제거합니다.
반복형이므로 이력이 길어도 재귀 깊이 제한에 걸리지 않습니다.
시간 O(Va + Ea), 공간 O(Va)이며 Va, Ea는 방문한 조상 영역의 정점과 간선 규모입니다.

### merge_sort: 직접 구현한 안정 병합 정렬

입력을 절반으로 나누고 정렬한 뒤 병합합니다. key 함수로 날짜/작성자/목록 길이 기준을 바꿉니다.
비교 값이 같으면 왼쪽 값을 먼저 선택하므로 기존 입력 순서가 유지되는 안정 정렬입니다.

| 항목 | 복잡도 |
|---|---|
| 최선/평균/최악 시간 | O(N log N) |
| 추가 공간 | O(N) |
| 재귀 깊이 | O(log N) |

`sorted()`와 `list.sort()`를 사용하지 않습니다.
기본 LOG와 달리 옵션 LOG는 지정한 속성의 오름차순을 우선하며 위상 순서를 강제하지 않습니다.
동률이면 커밋 딕셔너리의 삽입 순서가 유지됩니다.

### InvertedIndex: 전체 순회를 피하는 검색

메시지를 `lower().split()`으로 토큰화합니다. 중복 토큰은 set으로 제거하여 같은 커밋을 중복 등록하지 않습니다.
`keywords[token]`과 `authors[name]`에 커밋 ID 목록을 누적합니다.

단일 토큰 및 작성자 검색은 평균 O(1 + K)입니다. K는 일치 결과 수이며 문자열 처리 비용은 별도입니다.
전체 커밋을 순회하는 검색의 O(V) 검사 대신 인덱스의 후보 목록만 확인합니다.
모든 커밋이 일치하면 결과 처리에 O(V)가 필요하므로 항상 상수 시간인 것은 아닙니다.
여러 토큰 검색은 가장 짧은 후보 목록부터 다른 후보 집합과 교집합을 구합니다.
토큰 수 q, 후보 목록 길이 합 S, 가장 짧은 목록 길이 m일 때 대략 O(q log q + S + m*q)입니다.

### execute와 main

`shlex.split`으로 따옴표 포함 인자를 해석하고 명령어만 대문자로 정규화합니다.
`execute`는 인자 검증과 명령 분기를 담당하며 종료 명령에 False를 반환합니다.
`main`은 입력 → 실행 → 출력 루프를 유지하고 사용자 입력 오류를 잡아 다음 명령을 받습니다.
EOF와 Ctrl+C도 정상 종료로 처리합니다.

## 6. 오류 처리

| 상황 | 메시지 |
|---|---|
| 초기화 전 사용 | Repository not initialized |
| 인자 누락/초과, 빈 문자열, 닫히지 않은 따옴표 | Invalid args |
| 잘못된 옵션 | Invalid args |
| 없는 브랜치 | Unknown branch: 이름 |
| 없는 커밋 | Unknown commit: ID |
| 중복 브랜치 | Branch already exists: 이름 |
| 재초기화 | Repository already initialized |
| 알 수 없는 명령 | Unknown command: 명령 |
| 빈 HEAD 병합 | Cannot merge empty branch |
| 동일 HEAD 병합 | Cannot merge identical heads |

## 7. 테스트

```bash
python -m unittest -v
```

제공본은 자동 테스트 12개를 실행해 모두 통과했습니다.

검증 범위: 부모 우선 순서와 병합 부모, 사전순 최소 최단 경로, 연결되지 않은 그래프,
중복 없는 조상 탐색, 키워드/작성자 검색, 중복 토큰과 복수 작성자 인덱스,
정렬 안정성과 비교 기준, 로그 옵션, 공백·한글·대소문자 파싱과 오류,
병합 오류, ID 범위 초과, 금지된 정렬 API 호출 여부입니다.
테스트 성공은 모든 가능한 입력에 대한 완전한 검증을 의미하지 않습니다.

## 8. 범위와 제한

- 실제 파일 내용 추적, 네트워크 통신, 디스크 영속성은 구현하지 않습니다.
- MERGE는 두 부모를 연결하는 메타데이터 모델입니다. 파일 충돌 해결과 fast-forward 판정은 없습니다.
- DIFF 및 두 가지 이상 정렬 알고리즘 성능 비교는 선택 과제로 남겨 두었습니다.
- CLI에서 작성자는 INIT으로 한 번 설정됩니다. 작성자 변경 명령은 없습니다.
- 작성자 정렬 함수는 다양한 작성자도 처리하지만 한 CLI 세션에서는 모든 커밋 작성자가 동일합니다.
- 그래프 전용 외부 라이브러리와 표준 정렬 API를 사용하지 않습니다.
